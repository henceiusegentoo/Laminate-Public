= Laminate Standalone Internals
:toc: left
:toclevels: 4
:sectanchors:
:sectlinks:
:source-highlighter: rouge

This document describes the internal design and implementation of `laminate-standalone`, a
from-scratch launcher and mixin runtime that adds first-class support for _hybrid plugins_ —
standard Bukkit/Paper plugins that may also register SpongePowered Mixin bytecode
transformations against the live server — on top of an official, completely unmodified Paper
build, without requiring operators to supply manual JVM flags or install a separate mod loader.

Unlike the project this one replaces (a full source fork of Paper, frozen and preserved as a
historical proof of concept), `laminate-standalone` does not patch or fork a single line of
Paper's own source. It treats an official "paperclip" server jar as a build input: downloaded
and sha256-verified at *Gradle build time*, then merged with this project's own launcher, mixin
runtime, and always-on core mixins into one bootable `laminate-server-<mcversion>.jar`. Updating
to a newer Paper release is, in the common case, bumping one property in `gradle.properties` and
rebuilding — there is no patch stack to rebase and no merge conflicts to resolve by hand.

Every question about how the server starts, how the mixin runtime is bootstrapped without a
forked `PaperBootstrap` hook to call into, how Paper-internal UX behaviors (failed-plugin
culling, `/reload` blocking, `/plugins` categorization) are reproduced as ordinary mixins instead
of source edits, and how `laminate-api` tools work for hybrid plugin authors should be answerable
from the sections that follow.
